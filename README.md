# Нетослово

**Нетослово** — игра, в которой нужно угадать загаданное слово, ориентируясь на его близость к предыдущим вариантам. После каждой попытки игрок получает позицию своего слова в заранее рассчитанном списке, отсортированном по семантической близости к загаданному слову.

Техническое название проекта — **WordoGuessr**. Оно используется во внутренних именах приложений, конфигурации и отдельных элементах инфраструктуры.

Репозиторий содержит:

- .NET-бэкенд и миграции базы данных: `src/api`;
- Vue-фронтенд: `src/ui`;
- общие .NET-библиотеки: `src/api/Common`;
- локальную Docker Compose-инфраструктуру, тестовые данные и дашборды: `deployment`.

## Архитектура

- Бэкенд: modular monolith на .NET 10 с модулями Auth, Game, Words, Email и Sagas. Границы модулей заданы отдельными проектами `Domain`, `App`, `Infra`, `Contract` и `API` там, где соответствующий слой нужен.
- Фронтенд: Vue 3, TypeScript, Vite и PrimeVue.
- Хранение данных: PostgreSQL как основное хранилище; Redis для кэширования и ключей Data Protection. В локальном окружении используются Redis-совместимые экземпляры Valkey.
- Сообщения и фоновые задачи: Wolverine с хранением сообщений в PostgreSQL.
- Тестирование: xUnit; интеграционные тесты поднимают PostgreSQL через Testcontainers.
- Наблюдаемость: логи и метрики экспортируются через OpenTelemetry. Локальный стек включает Grafana, VictoriaMetrics и VictoriaLogs.
- Доставка: Docker-образы API и UI публикуются в GHCR; приложение разворачивается в Kubernetes из отдельного GitOps-репозитория.

## Разработка

Для разработки бэкенда требуется **.NET 10 SDK**, для фронтенда — **Node.js 24**. Используемая версия pnpm зафиксирована в `src/ui/package.json`.

Полная конфигурация локального окружения находится в `deployment/docker`.

Перед первым запуском:

1. скопируйте `.env.example` в `.env`;
2. замените в `.env` все пути и пароли на ваши значения для локального окружения;
3. запустите `run-app-with-deps.sh` или `RunAppWithDeps.ps1`.

Docker-прокси публикует приложение по адресу `https://wordoguessr.localhost`. Для работы HTTPS локальный сертификат должен быть добавлен в доверенные.

Значения вроде `changeme`, а также сохранённый в репозитории ключ хеширования OTP предназначены исключительно для локальной разработки. По умолчанию порты сервисов Docker Compose доступны только через loopback-интерфейс.

### Отладка в VS Code

В репозитории есть готовые конфигурации `.vscode/tasks.json` и `.vscode/launch.json`. Перед отладкой выполните шаги первого запуска выше, запустите Docker и установите зависимости фронтенда командой `pnpm install --frozen-lockfile` в каталоге `src/ui`.

Откройте корень репозитория в VS Code, перейдите в **Run and Debug** и запустите одну из конфигураций:

- `Debug API` — собирает и запускает API вместе с необходимыми Docker-сервисами, затем открывает Scalar по адресу `http://localhost:5292/scalar`;
- `Debug API (migration mode)` — запускает API в режиме применения миграций;
- `Debug API + UI + proxy (host_mode)` — запускает API, dev-сервер UI и локальный proxy, затем открывает `https://wordoguessr.localhost`.
- `Debug API + UI + proxy (cloudpub)` — запускает API и dev-сервер UI локально, а Caddy и CloudPub — через `compose.proxy.cloudpub.yaml`; открывает локальный адрес `http://localhost:8089`.

Для профиля CloudPub задайте `CLOUDPUB_TOKEN` в `deployment/docker/.env`. UI и API публикуются с Basic Auth. Этот профиль использует Docker host networking, как и `host_mode`, и требует свободных портов `5292`, `5173` и `8089`.

Связанные задачи автоматически собирают API и поднимают нужные зависимости через Docker Compose. После остановки отладки созданный для неё Compose-стек удаляется автоматически.

## Валидация и публикация артефактов

Для pull request отдельно запускаются обязательные проверки бэкенда и фронтенда.

После попадания изменений в `main` отдельный workflow выполняет сканирование и публикует Docker-образы API и UI в `ghcr.io/netoslovo`. Образы получают теги с SHA исходного коммита.
